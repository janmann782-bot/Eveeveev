# Тимофей AI 2.0

Новостная редакция САР Кефирстан и Тимофей Рализм для Telegram. Python 3.11+, aiogram 3, SQLite FTS5, асинхронный xKiro с выбором любой модели из каталога, включая бесплатные Mistral и Qwen. Код полностью переписан. Старое состояние сохранено в ветке `backup/pre-rebuild-2026-10-29`, история Git сохранена

## Запуск

Из корня репозитория:

```bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows: .venv\Scripts\activate
python -m pip install -e '.[dev]'
cp .env.example .env
# В Windows можно просто скопировать файл вручную
python -m timofey check
python -m timofey
```

В `.env` заполни `BOT_TOKEN` и `XKIRO_API_KEY`. Для выбора модели используется `AI_MODEL` (по умолчанию `mistralai/mistral-large-2512`). Старый `MINIMAX_MODEL` поддерживается как запасной вариант, если `AI_MODEL` не задан. При смене модели в личке владельца выбор сохраняется в SQLite и имеет приоритет при запуске. Не присылай их в GitHub, issues или этот репозиторий. Ключи не требуются для тестов. `.env` и `runtime/` исключены из Git. Для прокси поддерживаются унаследованные HTTPS_PROXY/HTTP_PROXY у xKiro и TELEGRAM_PROXY или HTTPS_PROXY у Telegram. TLS-проверка включена

Бот должен быть администратором канала **@SAR_Kefirstan** с правом публикации и администратором привязанной группы **@Kefirstano**. При первом запуске getChat проверит привязку в обе стороны и права бота, определит числовые ID и пришлет их владельцу **7787565361**. Запиши их в CHANNEL_ID и DISCUSSION_ID для дальнейших запусков. Проверки входящих обновлений всегда используют числовые ID. Участники других чатов и личек игнорируются

На новом состоянии автопостинг **выключен**, режим **manual**. `/admin` открывает кнопки и список команд. Для расписания черновиков `/autopost on`. Для самостоятельной публикации после тестирования `/mode automatic`. `/pause` приостанавливает генерацию, ответы и публикации, `/stop` останавливает процесс. После /stop для повторного запуска нужен доступ к хостингу

Проект не включает хостинг. Для постоянной работы нужен 1 постоянно запущенный процесс и постоянный диск для `runtime/`. Не запускай несколько экземпляров с одним токеном. Локальная блокировка предотвращает 2 процесса с одной папкой данных, но не на разных серверах

## Ключ и модель в личке владельца

```text
/key НОВЫЙ_КЛЮЧ
/model mistralai/mistral-large-2512
```

`/key` без аргумента показывает только наличие ключа. С аргументом бот пытается удалить сообщение, заменяет XKIRO_API_KEY в окружении текущего процесса, не повторяет значение и не пишет его в SQLite. Если удалить сообщение нельзя, владелец получает предупреждение. После перезапуска берется окружение сервера/.env. Для постоянной смены обнови секрет на хостинге. Это намеренно: Telegram-команда не создает скрытое файловое хранилище ключей

`/model` без аргумента показывает модель. При смене проверяются формат ID и наличие модели в живом каталоге xKiro. Поддерживаются любые провайдеры, в том числе Mistral, Qwen и MiniMax. Ошибка оставляет прежнюю модель. Успешный выбор сохраняется после перезапуска. Выбрать платную модель можно, но команда предупреждает: ее генерация заблокирована. Перед каждым запуском генерации отдельно проверяются бесплатный tier и нулевые цены, результат проверки кешируется на 5 минут. Выбор модели не разрешает денежное списание. Автоматического перехода на другой API или платную модель нет

### Подарочные токены xKiro - незавершенная внешняя настройка

HTTP-интеграция реализована, но ключ и подарочный пакет аккаунта в среде разработки отсутствовали. Публичная документация не дает надежного механизма запретить списание денег после исчерпания/истечения подарка. Бот допускает **только подтвержденный бесплатный маршрут выбранной модели**, независимо от провайдера. Если бесплатный маршрут не подтвержден, генерация блокируется с `NO_VERIFIED_FREE_MODEL_ROUTE`

В `.env.example` задан `mistralai/mistral-large-2512`, указанный в публичном каталоге как бесплатный. Прямой GET каталога 29.10.2026 подтвердил все 9 MiniMax с `access_tier=paid`: бесплатного маршрута MiniMax сейчас нет, платный выбор блокируется с `PAID_ROUTE_BLOCKED`. Список моделей меняется, альтернативная платная модель автоматически не подставляется. Для использования именно подарочного пакета потребуется проверить его правила с ключом аккаунта и документированный серверный запрет денежного fallback. Разрешение тратить деньги в проект не заложено

## Что реализовано

- Локальная база канона из актуальной выгрузки вики с BM25-поиском и ограничением объема контекста. Поиск выполняется для каждой генерации и проверки. Весь лор в системный промпт не помещается
- 3 раздельных слоя: подтвержденный канон, новости канала, память граждан. Загрузка нового лора доступна только владельцу: `/lore Заголовок | Текст` или UTF-8 txt/md до 100 КБ
- 75% новых историй, 15% продолжений, 5% пересечений, независимые 5% рубрики “Белая горячка Тимофея Рализма”. При пустой или закрытой истории продолжение/пересечение заменяется новой новостью. Специальные 5% не перераспределяются
- 18 тем, ротация мест, исключение последних 3 тем для новых историй, учет последних публикаций, текстовый контроль повторов. Максимум 2 продолжения, закрытые линии не возрождаются. Спецвыпуски не продолжаются
- Новости сохраняют тип, время создания/публикации, место, персонажей, организации, связи, последствия и статус линии. Канон не меняется от публикации
- 6 форм ответов, включая отдельный проверяемый режим из 1 слова. Вероятность, общая и персональная задержки, память собеседника. Только комментарии под постами целевого канала и продолжения этих обсуждений. Сообщения ботов, анонимных отправителей и команды в группе игнорируются
- Закрытые предпросмотр, редактирование, публикация, удаление черновика, расписание и режимы. `/help` перечисляет все команды, включая память, лор, токены, ошибки и управление работой
- Глобальный лимит вызовов в минуту, суточный бюджет, резервирование токенов до запроса, отчет фактического usage, ограниченные повторы 429/5xx и автоматическое закрытие генераций при серии ошибок. Ошибки и неопределенные затраты сохраняются после перезапуска
- Проверка канона отдельным вызовом перед сохранением новости/ответом и после редактирования. Это дополнительная проверка моделью, а не доказательство безошибочности: до оценки живых текстов рекомендуется manual
- Публикация через переход draft → sending → published. При таймауте sending → uncertain, автоматического повторения нет. `/uncertain` и `/reconcile ID MESSAGE_ID` позволяют владельцу отметить доставку после проверки канала. Telegram Bot API не гарантирует exactly-once sendMessage

## База и обновление канона

```bash
python -m timofey import-wiki /путь/Aurelia_Wiki_updated.xml
```

Замени knowledge/canon.jsonl новым результатом и перезапусти процесс. Загруженные владельцем дополнения сохраняются отдельно от заменяемого корпуса в SQLite. Источники и расхождения со старой памятью описаны в [docs/SOURCES.md](docs/SOURCES.md)

`runtime/state.sqlite3` содержит настройки, добавленный лор, переписку, события, журнал ошибок и затраты. Память каждого гражданина ограничена числом сообщений и сроком хранения, технические сообщения и ID обновлений также очищаются. Перед обновлением делай SQLite backup API или останавливай процесс и копируй всю папку runtime вместе с WAL. Не копируй только живой файл базы отдельно от WAL

## Проверки

```bash
python -m pytest -q
ruff check timofey tests
python -m timofey check
python scripts/check_secrets.py
```

Тесты работают с mock xKiro и настоящим aiogram Dispatcher, без платных запросов и публикаций. Проверяются распределение 100 000 независимых выборов, генерация и спецрежим, история, закрытие линий, память, 1 слово, права, поддельные кнопки, смена ключа/модели (включая Mistral), каталог и запрет платных маршрутов, недоступность API, таймаут отправки и повторные обновления

Живые ответы MiniMax, качество шуток, устойчивость к сложным обходам инструкций и фактическая доставка в Telegram без ключей не проверены. Числовые ID канала/группы будут подтверждены getChat при запуске. После запуска проверь `/news`, `/delirium`, предпросмотры и 1 ручную публикацию, затем ответы в комментариях. Автоматический режим включай после этой проверки
